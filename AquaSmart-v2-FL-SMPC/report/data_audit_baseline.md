# AquaSmart dataset audit — baseline (10 November 2026)

**Branch:** research/improve-experiments  
**Source:** 11 IoTPond CSVs from the fork of abirmhamdi/AquaSmart.  
**Data provenance:** https://www.kaggle.com/datasets/ogbuokiriblessing/sensor-based-aquaponics-fish-pond-datasets  
**Status:** first-pass audit by direct scanning of the raw CSVs. The committed Python script fl_smpc/audit_dataset.py can be run locally to independently regenerate diagnostic reports.

## 1. Key conclusion

The IoTPond files contain observed environmental and fish measurements but **no measured feed ration/intake label**. Current fl_smpc/data.py constructs feed_ration_g from fish weight, temperature, dissolved oxygen and pH, plus random noise. The present R2/RMSE results therefore evaluate learning a **synthetic rule**, not real-world optimal fish-feed prediction. This distinction must appear in the paper.

Additional observations:
- **200,018** raw records show dissolved-oxygen values above 20 (review units and sensor scale; do not automatically classify as physically impossible).
- IoTPond7 has a high volume of incomplete essential measurements; investigate its time segments and missingness rather than treating these rows as independent random losses.
- IoTPond10/11/12 contain only 581/2,616/3,589 retained records, so client sizes are highly imbalanced.
- The logged experiment samples up to 15,000 rows per pond after filtering, rather than using all 782,353 valid rows.

## 3. Units and metadata must be verified

The raw headers differ: many files label dissolved oxygen, ammonia and nitrate as **(g/ml)**; IoTPond8 labels them **(mg/L)**; some smaller files omit units entirely. Values such as nitrate >100 are widespread, making universal clipping at 100 without unit validation scientifically questionable. Do not apply a conversion until the original dataset documentation establishes the correct sensor scale.

Timestamps also vary: created_at, Date, DATE and mixed timestamp formats. The normalization function currently drops timestamps, making chronological validation impossible downstream without changes.

## 4. Methodological issues identified in code

1. **Synthetic outcome:** target is generated by _derive_feed_target and should be labelled simulated, not measured.
2. **Potential test contamination:** centralized.py uses an independent pooled train/test split while evaluate() uses a different per-client test set; some evaluation records may occur in central training.
3. **Preprocessing leakage:** the shared RobustScaler in centralized.py, local.py and federated.py is fitted on concatenated observations **before** creating the held-out sets.
4. **Temporal leakage:** randomly splitting closely spaced pond sensor observations can overestimate generalization to future periods. Preserve, parse and use timestamps.
5. **Client interpretation:** one pond is one **simulated FL client**; the dataset does not establish 11 independent farm operators.
6. **Privacy claim:** the current simulator pools all client records in process for scaling/evaluation; it is not a deployment demonstrating distributed privacy guarantees.

## 5. Proposed actions (ordered)

- [ ] Verify primary dataset attribution, original units, acquisition conditions, and admissible quality ranges.
- [ ] Produce the read-only per-pond audit by running python -m fl_smpc.audit_dataset.
- [ ] Preserve timestamp and pond identifiers through data cleaning; agree on common chronological train/validation/test split.
- [ ] Reuse **exactly the same held-out observations** in centralized, local, FL and FL+SMPC experiments.
- [ ] Fit preprocessing using training-only information; describe the privacy cost of global scaling and evaluate a deployable alternative.
- [ ] Keep synthetic-label learning as a clearly marked proof of concept, or obtain independently measured feed rations for the main predictive claims.
- [ ] Re-run baselines under multiple seeds; report per-pond and aggregate metrics.
- [ ] Only then assess secure aggregation (actual client-held masks/keys, collusion assumptions, dropout and overhead).
